# Hypothesis H4 — done-definitions stated before the work begins

Claim: the artists handle key frames well because each packet states
its done-definition before any work starts, so the result is judged
against a standard the worker saw in advance — and, in the packet
cases, the definition is executable: a hash, a count, a correlation.

Evidence walked:
- Gate 1's packets (30.7.9/8.7.13/9.6.9) define done as checkable
  facts: a file on disk at the archive's exact byte size with its
  sha256 recorded; a page frame for every shot in the timing map;
  an animatic at full runtime. Each return is a binary pass against
  its definition.
- Batch 2.1's definition (27.6.9/8.6.11/7.6.9) demands a per-frame
  table with zero unexamined frames and any failing frame named
  individually — the return (18.13.15/9.12.15/13.14.16) is exactly
  that table.
- Qualification the evidence forces: the generated clips also worked
  under written done-definitions (the ladder's, in the animator
  skill) and failed them repeatedly (24.7.9/8.7.11/7.6.8,
  25.8.8/9.7.12/7.6.9, 25.7.10/8.6.10/7.6.9). A definition does not
  make work succeed; it makes success and failure decidable. What
  distinguishes the packet cases is that the definition and the
  verification are the same shape — the check is run, not eyeballed.

Verdict: SUPPORTED with that refinement: pre-stated definitions
explain why artist work is verifiably good, and executable
definitions explain why meeting them is a fact rather than a taste.
