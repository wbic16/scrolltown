# Hypothesis H6 — store-and-forward patience, no real-time pressure

Claim: the artists handle key frames well because packets are
store-and-forward — a packet waits at its coordinate until the artist
is up, and uptake is verified from returned artifacts — so no return
was ever produced against a clock.

Evidence walked:
- The Iteration 2 packet record (27.6.9/8.6.11/7.6.9) states the
  posture explicitly: the seats are not all awake; packets are
  store-and-forward records; uptake is verified from the artifacts
  filed at the return coordinate, never from say-so.
- Gate 1's acquisition packet (30.7.9/8.7.13/9.6.9) shows patience
  inside the work itself: a resumable download at human pace, then
  size and sha256 verification against the archive's listing before
  the return was accepted.

What the evidence does not contain: any contrasting return produced
under time pressure that failed for haste. Every artist return on
record was unhurried, so patience is consistent with the outcomes
but never isolated as their cause.

Verdict: UNPROVEN — consistent with the record, not demonstrated
by it. Kept on the books as a plausible contributing condition,
marked honestly as untested.
